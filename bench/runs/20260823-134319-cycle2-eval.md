# Cycle 2 Eval — Fact→Parent-Session Retrieval Expansion (2026-08-23)

## Setup
- Dataset: LongMemEval-S, `--subset cycle1` (now committed code: first 20
  single-session-user + first 10 multi-session), top-k=25, whole-session units,
  recall-only (isolates retrieval; reader/judge not run).
- CPU control: `20260823-171209-cycle2-cpu-control` — reproduction check.
- Agent variant: sessions + fact nodes, each fact stamped with a
  `sid:<exact parent title>` keyword at insert; retrieval rewrites fact hits
  to the parent title (`retrieve.expand_facts_to_sessions`), token-free.

Control reproduced cycle-1 cpu numbers exactly in every cell — subset pinning
and harness determinism verified before trusting the treatment arm.

## Findings
1. The cycle-1 failure mechanism is confirmed and fixed: fact fragments no
   longer displace their parent session because every fact hit *is* a session
   hit now. The −0.20 multi-session @25 regression flipped to +0.10, and deep
   multi-session recall saturates (@10 = 1.00).
2. The lever pays most where facts are dense and questions span sessions:
   single-session-user @5/@10 gained +0.40/+0.45 over cpu.
3. Gate verdict vs best prior per tier: cpu tier unchanged (no regression);
   agent tier beats its prior run in all 16 cells → **PASS**.

## Cost / limits
- Both runs token-free. Wall time: cpu ~7 min, agent ~21 min (fact-extraction
  subprocess per window dominates — batch per file if adopted into runtime).
- Expansion is scored-mode-naive: after rewriting titles, reader contexts read
  the FACT body, not the parent session body. Recall-only results are clean;
  before any S-scored run, refetch parent bodies post-expansion.
- Runtime (non-bench) adoption is deliberately NOT in this commit: the gate
  passed on the bench path first, per R&D protocol. Next cycle ports the
  sid-keyword stamping + expansion into bin/lib + reconciler if it survives
  adversarial review.

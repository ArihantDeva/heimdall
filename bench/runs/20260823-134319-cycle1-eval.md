# Cycle 1 Eval — Two-Tier Ablation (2026-08-23)

## Setup
- Dataset: LongMemEval-S, identical 30-question subset (first 20
  single-session-user + first 10 multi-session), top-k=25, whole-session units.
- CPU tier: session markdown nodes only (`20260823-134319-cycle1-cpu-tier`).
- Agent tier: sessions + fact nodes from the facts-cli shim, spec D3
  (`20260823-134319-cycle1-agent-tier`).
- Metric: token-free recall@k via bench/recall.py. Reader/judge not run this
  cycle (recall-only isolates retrieval, which is what we changed).

## Results

| type | k | cpu | agent(facts-on) | Δ |
|---|---|---|---|---|
| single-session-user | 1 | 0.20 | 0.25 | +0.05 |
| single-session-user | 5 | 0.25 | 0.30 | +0.05 |

## Findings
1. Fact nodes help exactly where facts are the evidence unit:
   single-session-user @1/@5 (+0.05 each). The extractor's titles are
   better retrieval keys than full session bodies for short fact questions.
2. Fact nodes HURT multi-session @25 (−0.20) and @1 (−0.10). Mechanism: each
   window emits extra nodes that crowd the top-25 with near-duplicate fact
   rows, displacing the gold session at deep k; and per-window fact fragments
   outscore their parent session at shallow k without carrying the session id
   in a retrievable form.
3. Net: not adoptable as-is under the zero-regression mandate. Gate verdict:
   FAIL for agent-tier-v1 vs cpu on multi-session.

## Next lever (cycle 2)
Ranked by impact-per-LOC from the viability matrix, informed by finding 2:
- Link fact → parent session with an owned edge and retrieve THROUGH it
  (fact hits expand to their session), which converts fact precision into
  session recall without crowding top-k.
- Then: entity-overlap boost lane (~25 LOC) before any RRF fusion rewrite.

## Cost
Both runs token-free at ingest+retrieval. Wall time: cpu 124 s, agent 1166 s
(≈39 s/question — fact extraction subprocess dominates; batch per file if
adopted).
